# Development

Run the tests with `python3 scripts/test.py` (see [CONTRIBUTING.md](../CONTRIBUTING.md)). To look at the dashboard and click through it without a real install, use the sandbox. The look (colours, type, components) is described in [design.md](design.md).

## The sandbox

The sandbox runs the real app and dashboard from your checkout on made-up data, with a stand-in Network. It is meant for people and agents who want to see the interface, try interactions and catch layout problems.

```bash
scripts/sandbox.sh busy            # open http://127.0.0.1:8870; Ctrl-C stops it
scripts/sandbox.sh fleet,expired   # states combine
scripts/sandbox.sh all 8880        # another port, so two can run side by side
```

The sandbox uses three ports: the dashboard on the given port, the Network on port+1 and the app on port+2. Its data goes to `/tmp/machine-sandbox-<port>`, which is emptied on every start, so each run begins from the same state.

### States

| State | What you see |
|---|---|
| `fresh` | Just installed: two accounts, the first signals, no cards and no review yet |
| `reviews-off` | A normal day with reviews switched off |
| `busy` | A full day: every source, open, prepared and snoozed cards, promises, decisions and finished reviews |
| `fleet` | `busy`, in a work Fleet with three teammates (one without a Machine), their questions, a handoff, an intro, a seat request and an answered question of yours |
| `friends` | `busy`, with two friends, a request in and one out |
| `family` | `busy`, in a Family Fleet |
| `expired` | `busy`, with the work Google sign-in expired for Gmail and Calendar |
| `all` | `busy`, `fleet`, `friends` and `family` together |

### What is real and what isn't

- **Real:** `assistant.py`, `dashboard.html`, `fleet.py` and the rest of your checkout; the database schema; every dashboard action. A proxy on the dashboard port signs each request in as the owner, as Tailscale Serve does, so a browser on this machine can use everything.
- **Off:** collectors, reviews, preparation, delivery, model usage, embeddings and enrichment. Nothing syncs and no model is called.
- **Faked:** an approved send (email, Slack, WhatsApp, LinkedIn, X) is written to `sent.jsonl` in the data folder and shown as sent. Phone and Telegram notifications go there too.
- **The Network** (`sandbox/stub_network.py`) answers from memory. A teammate's Machine answers your question about three seconds after you ask it. Friend requests, accepting, blocking and seat decisions work.
- **Sealed:** `sandbox/guard.py` installs a Python audit hook that refuses any connection beyond 127.0.0.1, any name lookup and any program start, whatever code path tries. Each refusal is printed as `sandbox: refused …`. Some status checks start programs (for example the OpenClaw CLI), so a few refusals on startup are normal.

### Screenshots and layout checks

```bash
scripts/sandbox.sh shots all                         # start, shoot, stop; PNGs in /tmp/machine-shots/all
scripts/sandbox.sh shots fleet /tmp/shots 8880 --pages fleet,settings --widths 390 --themes dark
node sandbox/shots.mjs --url http://127.0.0.1:8870   # against a sandbox that is already running
```

`sandbox/shots.mjs` opens Suggestions, Calendar, Events, Graph, Projects (its board), Fleet, Feedback, Connections and Settings at 390px and 1280px, in light and dark. It saves a full-page PNG of each (`<page>-<width>-<theme>.png`) and `report.json`, and prints three checks:

- **overflow:** the page, or an element on it, is wider than the screen (content inside a scrolling or clipping box is fine);
- **overlap:** two visible buttons, links or inputs cover each other by more than 2px;
- **wrapped date:** a date or time breaks over two lines.

It also reports script errors from the page. Pass `--strict` to exit 1 when anything is found. Pages a state doesn't show (Fleet without a Fleet) are skipped. Chromium comes from `CHROMIUM_PATH`, else `/opt/pw-browsers`, else `/usr/bin/chromium`. Playwright comes from OpenClaw's install, else `playwright-core` or `playwright` on the module path. The browser only reaches the sandbox; every other request is aborted.

### The test data

`sandbox/fixture.json` is generated by `sandbox/fixture.py` (deterministic: `python3 sandbox/fixture.py > sandbox/fixture.json`). Its shape follows counts from a real install: signals per source per day, how many cards are open, closed or prepared, how long threads get. It holds no content from that install. The counts are in `sandbox/profile.json`, which `sandbox/derive_profile.py` makes from a copy of a database.

Every person, company, address, chat and id in the fixture is invented, and every address and link is on `.example`. `sandbox/check_fixture.py` enforces this:

```bash
scripts/sandbox.sh check                                   # static rules: .example only, no phone numbers
cp ~/.local/share/personal-assistant/events.sqlite /tmp/copy.sqlite   # or sqlite3 .backup; never the live file
python3 sandbox/check_fixture.py --db /tmp/copy.sqlite --config ~/.local/share/personal-assistant/config.json
rm /tmp/copy.sqlite
```

With `--db`, it collects every name, address, domain, company, chat and account id from that database (and the owner's name and accounts from the config), and fails if any of them appears in the fixture. It prints only how many matched and of what kind, never the values. Run it after changing `fixture.py`. `test_sandbox.py` runs the static rules and checks that the fixture is up to date.

Each open card has its own story in `STORIES`: its people, a thread with several messages both ways, and a draft written for it, so a card's chat, its sources and the Graph pages tell the same story. Everyone else (the crowd) writes about other topics and never shares a first or last name with a story's people. The fixture also holds a card handed to Claude Code with its result and two saved sign-ins (made-up placeholder passwords, sealed like real ones). The site's demo is recorded from this data.

To add data, edit `sandbox/fixture.py`: new names come from its invented pools, and new addresses use `.example`. To add a state, extend `sandbox/load.py` (`STATES` and `load`) and, for the Network, `sandbox/stub_network.py`.
